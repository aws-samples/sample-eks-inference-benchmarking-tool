# vLLM recipes

One manifest per row. Each serves exactly one model on one instance type at one precision, and pairs with the runbook that runs it.

Every supported ordinary serving recipe is validated by its sibling deploy helper before measurement. Run `eks-bench validate-manifests <model>/<recipe>.yaml` directly when you only need to prove that one recipe—including a specialized study recipe—passes the flags it is written to pass.

An unset `Parallelism` cell means the recipe passes no `--tensor-parallel-size`, so vLLM defaults to one GPU.

## Naming

`<model>/<precision>-<instance>[-<config>].yaml`. The instance is the full type, never the family tag, because the same model runs on different sizes within a family and the family alone hides the GPU count. A `<config>` suffix appears only to break a genuine collision, and names the axis that differs.

## What a recipe is not

A recipe runs `vllm serve`. Weight staging Jobs live in [`model-jobs/`](../model-jobs/README.md), quantization is a Job from [`k8s/examples/`](../k8s/examples/README.md), and infrastructure examples live there too. None of those belong here.
